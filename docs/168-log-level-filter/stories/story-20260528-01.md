# 維運者用 LOG_LEVEL 控制 daemon.log 的詳細程度

**日期**：2026-05-28
**想法**：marsen/Marsen.Backlog#168

## 互動關係

**As a** 維運者（跑 rai daemon 的人）
**I want** 用 `LOG_LEVEL` env 控制寫入 `~/.rai/logs/daemon.log` 的級別門檻
**So that** 平常 log 不被 DEBUG 噪音淹沒，排查問題時又能拉高到 DEBUG 看細節

### 主要流程

1. 不設 `LOG_LEVEL` → 預設 `INFO`，`log.debug(...)` 不寫檔也不輸出 console
2. 設 `LOG_LEVEL=DEBUG` → DEBUG 以上全寫，可見完整細節
3. 級別順序 `DEBUG < INFO < WARN < ERROR`，低於門檻一律不寫

### 邊界 / 例外

- 非法值（打錯字、空字串）→ 需有明確 fallback（見待釐清）
- `another instance is alive, exiting`（現 `info`）重新歸級為 `warn`，讓「正常但非預期」事件落在對的級別

## 拆分細節

- `FileLogger.write()` 加門檻判斷，直接讀 `process.env.LOG_LEVEL` 解析（已定不走 ConfigPort）
- `daemon-entry.ts` 的 `another instance is alive` 改 `c.log.warn(...)`
- `docs/architecture/conventions.md` 補例外條款：logger 配置允許 env fallback（專案原則禁止 `process.env.X ?? 'default'`，此處明訂例外）

## 待釐清
