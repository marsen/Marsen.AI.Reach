# 維護者修改 socket server 時不需要看完整個 bot.ts

**日期**：2026-05-14
**想法**：#166

## 互動關係

**As a** 維護者  
**I want** bot.ts 的每個職責都在獨立的模組裡  
**So that** 修改其中一塊時只需要看那一個檔案

## 拆分細節

- 3a：抽出 Unix socket server（IPC 與 rai CLI 溝通的邏輯）
- 3b：抽出 HTTP server（LINE webhook 啟動邏輯）
- 3c：抽出 signal handler（SIGINT、SIGTERM、SIGUSR1、uncaughtException）
  - 補上 `stopWatcher()` 呼叫：bot 關閉時應主動停止 watcher（目前缺失）
  - watcher 生命週期應與 **session** 一致（修正：原寫「與 bot 一致」）：
    - `StartSessionUseCase` 成功後 start
    - `StopSessionUseCase` / SIGUSR1 / session 失效偵測時 stop
    - bot 關閉（SIGINT/SIGTERM）時 stop（兜底）
  - 修正理由：bot 啟動時 tmux session 尚未建立，此時 watcher 輪詢只會讓 `tmux has-session` 持續失敗（stderr 噪音 + 無意義 IO）。已於 2026-05-15 在 bot.ts 落實，後續拆 signal handler 時繼承此設計。
