# 維護者理解依賴關係時不被跨層 import 混淆

**日期**：2026-05-14
**想法**：#166

## 互動關係

**As a** 維護者  
**I want** 各層只知道自己該知道的東西  
**So that** 修改某一層時不需要擔心意外影響其他層

## 拆分細節

- 2a：`AdapterDeps` 改用介面定義（不直接 import use cases、domain entity、infrastructure 具體型別）
- 2b：建立獨立的 composition root，由外層負責 wiring，adapter 只接收它需要的介面

- [ ] 待 `/flow:design` 填入

## 待釐清

- [ ] composition root 放在哪個層？`main.ts` 還是獨立模組？
- [ ] `AdapterDeps` 的介面要定義在哪一層？
- [ ] PC/TC 共享媒介目前是 tmux session（`rai` 透過 `tmux attach` 進入同一個 pane）。這是 infrastructure 細節暴露到使用者體驗層——設計上是否可接受？還是需要抽象層隔離？
- [ ] Session entity 與 tmux/Claude 外部狀態同步邏輯應放哪一層？目前散在 `presentation/bot.ts`（socket handler），wiring 重構時需要一併決定（application 層 use case 內？domain 服務？infrastructure adapter？）。具體未修問題見 [known-issues.md BUG-001](../../known-issues.md#bug-001session-entity-與外部資源狀態不同步)。
